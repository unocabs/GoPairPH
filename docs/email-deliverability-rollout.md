# Go Pair PH email deliverability rollout

The application code separates transactional and marketing messages, generates a
plain-text part, adds Reply-To and category tags, handles one-click marketing
unsubscribe, verifies Resend webhooks, and suppresses permanent failures. Gmail
still makes the final tab-placement decision; Primary Inbox placement cannot be
forced or guaranteed.

## 1. Apply the database migration

This project does not auto-apply Supabase migrations. Run
`supabase/migrations/048_email_deliverability.sql` manually in the Supabase SQL
Editor before deploying the application changes.

Existing and new profiles start with marketing email disabled. A user must opt in
from Edit Profile before appearing in an admin blast recipient list.

## 2. Configure inbound forwarding with Resend

In Resend, open **Emails > Receiving**, add `gopairph.com` as a custom receiving
domain, and copy the exact MX record Resend generates into the `gopairph.com` DNS
zone in Vercel. Do not use a third-party forwarding provider and do not invent an
MX value; use the value displayed for this Resend account.

Add the production destination inbox as `EMAIL_FORWARD_TO`. The verified webhook
accepts `email.received` events for only `hello@gopairph.com` and
`dmarc@gopairph.com`, then forwards the original content and attachments to that
inbox through Resend. Mail for any other address is ignored.

Confirm both addresses forward successfully before setting
`RESEND_REPLY_TO_EMAIL=hello@gopairph.com`.

## 3. Authenticate the Resend sending domain

Add `gopairph.com` as the sending domain in Resend. Copy the exact SPF/MX and
DKIM records generated by Resend into Vercel DNS.

Only after the domain shows **Verified** in Resend, configure production:

```text
RESEND_TRANSACTIONAL_FROM=Go Pair PH <notifications@gopairph.com>
RESEND_MARKETING_FROM=Go Pair PH <news@gopairph.com>
RESEND_REPLY_TO_EMAIL=hello@gopairph.com
```

Separate sending subdomains such as `notify.gopairph.com` and `news.gopairph.com`
are optional future upgrades only. Do not use them while the Resend plan allows a
single domain.

In Resend domain settings, leave open and click tracking disabled if possible.
Transactional templates use direct `https://gopairph.com`
links.

## 4. Publish DMARC in monitoring mode

Add this TXT record in Vercel DNS:

```text
Name: _dmarc
Type: TXT
Value: v=DMARC1; p=none; rua=mailto:dmarc@gopairph.com; adkim=r; aspf=r; pct=100
```

Review reports for at least two weeks. When all legitimate sources align, move to
`p=quarantine; pct=25`, then `pct=100`, and finally `p=reject`. Do not tighten the
policy while legitimate sources fail alignment.

## 5. Configure Resend webhooks

Create a webhook in Resend pointing to:

```text
https://gopairph.com/api/webhooks/resend
```

Subscribe to at least `email.received`, `email.delivered`, `email.bounced`,
`email.complained`, and `email.suppressed`. Copy its signing secret to
`RESEND_WEBHOOK_SECRET`. Generate a
separate random value of at least 32 characters for `EMAIL_UNSUBSCRIBE_SECRET`.

The webhook stores service-role-only delivery events. Complaints, provider
suppressions, and permanent bounces prevent subsequent sends. Temporary bounces
are recorded without permanently suppressing the address.

## 6. Validate and warm up

1. Send one example of each transactional category to controlled Gmail accounts.
2. In Gmail **Show original**, confirm SPF, DKIM, and DMARC are all `PASS`, and the
   visible From domain aligns with authentication.
3. Reply and confirm the message reaches `hello@gopairph.com` forwarding.
4. Confirm each message has readable HTML and plain-text parts, one clear action,
   and no promotional content mixed into account notifications.
5. Opt a test profile into marketing, send a test campaign, and verify both the
   visible unsubscribe link and one-click POST disable marketing only.
6. Trigger signed and intentionally invalid webhook requests; invalid signatures
   must return HTTP 400.
7. Register `gopairph.com` in Google Postmaster Tools. Keep reported spam below
   0.1% and pause nonessential sends if
   complaints, bounces, or deferrals rise.

Warm the root domain using ordinary low-volume marketplace events before sending
larger promotional campaigns. Send marketing only to explicit opt-ins from
`news@gopairph.com`.
